# F1. Purpose and scope

## Purpose

Provide one small, composable language for the accepted V0 surfaces so that later prototype work can express truth, authority, uncertainty and consequence consistently. The foundation should make the product feel related across surfaces while allowing each surface to use an appropriate density and emphasis.

## In scope

- visual principles and semantic token layers;
- typography roles;
- spacing, layout, shape, border and elevation foundations;
- responsive and accessibility principles;
- interaction outcome language and consequential-action presentation;
- a bounded primitive inventory;
- rules for composing domain patterns from primitives;
- reconciliation guidance for any legacy visual material;
- design dependencies that remain TBD.

## Out of scope

F1 does not decide product rules, payment economics, Inventory precedence, role authority, credential mechanism, expiry, cancellation/refund, Emergency Protective Hold or Temporary Commitment duration, Admin/BQL grants, Attention lifecycle, domain states, new actors or new workspaces. It does not create UI code, CSS/token files, routes, prototypes, a Figma library or CP8-G work.

## System posture

The foundation is implementation-aware for Next.js, React, TypeScript, Tailwind and shadcn/ui/Radix-style primitives, but is not bound to a particular API or CSS naming scheme. Token names in F1 are semantic examples for review, not an implementation contract.
