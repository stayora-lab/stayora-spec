# F1. Typography foundation

Typography should support marketplace clarity, Guest Stay legibility, operational scanning and reliable evidence without becoming an oversized marketing system.

## Minimal roles

| Role | Use |
|---|---|
| Display | Limited public marketplace or destination expression; never required for operational work. |
| Page title | Names the current responsibility or primary destination. |
| Section heading | Groups a meaningful information or action area. |
| Object title | Names a Property, Unit, Request, Booking, Stay, Incident or case in context. |
| Body | Explanatory and decision-supporting text. |
| Compact body | Dense list/table descriptions where readability remains safe. |
| Label | Field, action and control labels; labels remain explicit. |
| Metadata | Provenance, actor/context, timestamps, source and supporting qualifiers. |
| Numeric/tabular | Dates, amounts, counts and identifiers that benefit from aligned scanning; never use numeric styling to imply financial authority. |

Roles are semantic, not fixed pixel prescriptions. The eventual font family, weight mapping, line-height, locale behavior and exact scale remain design decisions for later F work. A restrained hierarchy is preferred over many arbitrary sizes.

## Application guidance

- Marketplace can give Display and Object title more room, while preserving readable body and price hierarchy.
- Guest Stay Access favors clear Object title, Body and actionable labels at mobile reading distance.
- Host/Sale workspaces use Page title, Object title, Compact body and Metadata for scanability.
- Butler, Destination/BQL and Admin may use denser Compact body and Numeric/tabular roles, but never at the cost of field readability or accessible zoom.
- Dialogs and consequential actions use a clear title, scope/actor summary, consequence text and outcome message; metadata is secondary but reachable.
