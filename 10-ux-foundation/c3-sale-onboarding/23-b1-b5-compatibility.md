# B1–B5 compatibility

| Baseline | C3 compatibility result |
|---|---|
| B1 Sale-assisted Booking | Sale onboarding supports scoped discovery, option preparation, Guest intent and Request creation; Host/delegated Booking Authority still accepts or rejects. |
| B2 External Booking → Stay | Sale may report external information; relationship/eligibility alone cannot create authoritative External Accommodation or Inventory Commitment. |
| B3 Direct Guest Booking | Direct Guest path remains independent; C3 does not require Sale or change Request/Booking semantics. |
| B4 Stay Operations | Sale commerce does not become Host/Butler/BQL/Guest operations authority. |
| B5 Inventory Intervention | Sale consumes derived Availability/Bookability but cannot mutate Inventory without a separate explicit capability. |

No accepted journey is redesigned or silently changed.
