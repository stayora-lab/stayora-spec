## Core reasoning chain

```text
IDENTITY
  → WORKING CONTEXT
  → RESOURCE SCOPE
  → RESPONSIBILITY
  → TASK / USER GOAL
  → DOMAIN OBJECT
  → AUTHORITY
  → SURFACE
  → INTERACTION
```

Working Context changes perspective and navigation. It does not create permission. Visibility is not authority; a user may see an object needed for a responsibility without being allowed to change it.

## Protected boundaries

CP8-A keeps the canonical distinctions in [CP3 authority](../03-actor-authority/00-authority-model.md), [CP4 lifecycle map](../05-state-machines-policies/00-lifecycle-map.md), [CP5 boundaries](../06-v0-scope/05-domain-boundaries.md), [CP6 context model](../07-information-architecture/02-context-model.md) and [CP7 conceptual principles](../08-conceptual-data-model/01-conceptual-model-principles.md). In particular: Identity is not Role; Role is not Permission; Relationship is not Authority; Ownership is not Hosting Authority; Working Context is not Permission; Platform Eligibility is not a Commercial Relationship; Request is not Booking; Booking is not Stay; External Accommodation Fact is not an Inventory Commitment; External Accommodation is not Stayora Booking; Inventory Commitment is not Availability; Availability is not actor-specific Bookability; Searchability is not Availability; Payment is not Entitlement; Settlement is not Payout; Incident/Finding/Responsibility/Consequence remain separate; Verification Review is not Verification Status; Review is not Reputation; Review Right is not an automatic consequence of checkout.
