# B5 — Owner Block Journey

> Status: **DRAFT — FOUNDER / PRODUCT ARCHITECT REVIEW** · **NOT FROZEN**

## Canonical path

```text
Owner/authorized Host intent
  → resource + Unit × Time + reason/provenance
  → authority evaluation
  → existing Inventory truth evaluation
  → authorized Owner Block decision
  → effective block / conflict if overlap
  → derived Availability and scoped projections
  → authoritative correction/release
```

## Boundaries

- Owner identity alone is not a universal technical permission. Resource relationship, acting capacity, scope and lifecycle must support the action.
- The block applies to a specified Bookable Unit and time range; B5 does not invent range granularity or reason taxonomy.
- A valid Owner Block can constrain derived Availability while effective.
- An Owner Block overlapping a Temporary Commitment, Confirmed Commitment, External Commitment, Maintenance Block or existing Stay preserves both truths and surfaces conflict/exception unless canonical policy says otherwise.
- Owner Block does not automatically cancel Booking, delete External Accommodation, cancel Stay, refund Guest, relocate Guest or select a conflict winner.
- Clearing/releasing the block restores only the relevant effective Inventory constraint; it does not make the Unit universally Bookable.

## Evidence and history

Record actual actor/capacity, authority basis, Unit, range, reason where canonical, effective time, source and correction/release history. A later change is an amendment/release/supersession, not destructive deletion.
