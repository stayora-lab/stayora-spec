# Resource-first journey

The resource-first path starts from a Property that is already known, newly represented, or created with Admin assistance. It deliberately allows the creator and the eventual Owner/Host to be different Identities.

| Step | Canonical effect | What remains pending when unknown |
|---|---|---|
| R1 Identify or represent Property | Establish the accommodation representation | Ownership and hosting are unresolved |
| R2 Associate Destination | Record candidate/accepted Destination membership | Membership is not BQL or commercial authority |
| R3 Represent Bookable Unit(s) | Link one or more Units to the Property where the resource truth permits | Inventory participation remains unresolved |
| R4 Identify/invite/claim Owner | Propose or establish Owner relationship through valid basis | Claim is not ownership truth |
| R5 Identify/invite/assign Host | Establish Primary Host or explicit Co-host scope | Owner does not automatically become Host |
| R6 Evaluate eligibility and authority | Attach only explicit capabilities and scopes | No creator/role shortcut |
| R7 Project readiness | Determine publication, Inventory, Booking or Stay-operations outcomes separately | No global completion state |

The Property may be useful as a private or administrative representation before Owner or Host truth is complete. Duplicate, conflict, and missing relationship paths preserve evidence and history; they do not choose a winner inside C2.
