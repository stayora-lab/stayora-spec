# Relationship and authority boundary

Relationship establishment and authority establishment are separate steps. C2 reuses CP3 capabilities only:

| Need | Canonical capability/basis | C2 boundary |
|---|---|---|
| Edit/represent Property | Property Authority with resource scope | Creator may have only the currently granted scope |
| Control publication | Property Authority plus publication conditions | Publication is not implied by ownership or hosting |
| Accept a Booking Request | Booking Authority | Owner/Host role alone is insufficient unless explicit authority exists |
| Manage Inventory | Inventory Authority | Ownership, Sale eligibility and whitelist are insufficient alone |
| Record External Accommodation | explicit Inventory capability | This may create Inventory truth and/or Stay context, not Stayora Booking |
| Manage Stay operations | Operations Authority/assignment and applicable context | Does not grant Booking or Inventory authority |
| Delegate Co-host | Delegation Authority | Only the permitted capability/scope can be delegated |
| View financial information/entitlement | separate financial capability and relationship | Host is not automatically beneficiary |

Where the canonical sources do not identify the grantor, acceptance rule, scope or privacy rule, the result is `AUTHORITY GAP/TBD`. Working Context changes visibility and navigation, never permission.
