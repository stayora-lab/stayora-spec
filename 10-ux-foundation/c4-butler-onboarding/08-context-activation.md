# Butler Working Context activation

Butler context becomes useful after Identity resolution, Butler capacity/eligibility, a valid Assignment and resource/function scope are sufficient. The context may project assigned Property/Unit, relevant Stay, arrival/departure, access, readiness, Incident and operational notes.

Context does not grant permission. Preparation, Check-in, Checkout, Incident or evidence actions each require the relevant action authority, lifecycle and policy. A Butler context cannot expose unrelated Properties, Stays, Guest history, payment, Owner/Sale economics or private authority structure merely because an Assignment exists.

No universal `BUTLER_ACTIVE` state is introduced; context usability is an outcome/projection.
