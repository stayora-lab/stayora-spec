# Butler entry modes

| Mode | Initiator / subject | Proposed Assignment | Eligibility / authority basis | Pending / failure boundary |
|---|---|---|---|---|
| Existing Identity assigned | Authorized assigning actor / existing Identity | Property, Stay or function scope where supported | Butler eligibility plus assignment authority | Assignment not automatic from identity |
| Invitation | Authorized operational context / invited Identity | Butler capacity or Assignment proposal | Invitation, consent and eligibility policy | Invitation is not Assignment or authority |
| Host-initiated | Host/Primary Host or delegated operational authority | Property/Stay responsibility | Explicit assignment authority and scope | Owner status alone is insufficient |
| Stayora Admin-assisted | Staff function / Butler Identity | Setup or correction within admin scope | Admin capability, reason and audit | Admin is not Butler or Host impersonation |
| Destination/BQL-assisted | Destination function / Butler Identity | Destination/property/stay function if canonically allowed | Destination/function scope; exact grant is TBD if silent | Visibility does not imply assignment authority |
| Manual V0 setup | Approved operational process / Identity | Scoped assignment and context | CP5 manual assistance plus provenance | No workforce scheduling or hierarchy |

Technical invitation, authentication, approval evidence and assignment UI remain unspecified.
