# CP8-D2 — Task & Screen Architecture

> Parent: **CP8 — UX / Design System** → **D — Workspace / Surface UX**
> Status: **ACCEPTED AS BASELINE FOR CP8-D3**
> Freeze status: **NOT FROZEN** · Scope: **D2 baseline for D3** · 2026-09-20

D2 translates accepted D1 surface responsibilities into the minimum coherent V0 task and screen architecture. It defines conceptual screen/view homes, canonical objects, information needs, authority-dependent action entry and cross-surface handoffs. It does not define visual UI, final navigation, detailed interactions, layouts, components, prototypes, APIs, persistence or implementation.

## Canonical derivation

`V0 requirement → journey/onboarding outcome → surface responsibility → user job → information need → action need → screen/view concept`.

Seven accepted surfaces remain canonical: Public Marketplace, Guest Stay Access, Host Workspace, Sale Workspace, Operations—Butler Context, Operations—Destination/BQL Context and Stayora Admin. Owner remains a perspective within Host/Property context unless a future accepted responsibility justifies more.

## Stop condition

D2 is the accepted task/screen baseline for [CP8-D3 Screen & Navigation Convergence](../d3-screen-navigation-convergence/README.md). CP8-E/F/G/H and implementation are not started by this pass.
