# Screen Derivation Rules

A screen/view concept is admitted only when the chain is explicit:

`CP5 V0 requirement → B/C journey outcome → D1 surface responsibility → user job → information need → action need → screen concept`.

## Structural types

`DISCOVERY`, `OVERVIEW`, `COLLECTION`, `DETAIL`, `ACTION ENTRY`, `ACTION FLOW PLACEHOLDER`, `ATTENTION / EXCEPTION`, `SCOPED ACCESS`, `CONTEXT / RESOURCE SELECTION` are conceptual categories. They are not routes or implementation page types.

## Boundaries

- List and detail remain distinct when collection triage and consequential object decisions require different responsibilities.
- A dedicated detail is justified only for truth/context/history, consequential action, handoff or exception inspection.
- Actions may originate from detail or an attention projection; D2 does not specify button placement, modal/drawer, form, confirmation, loading, toast or microcopy.
- Screen visibility never equals permission; every action re-evaluates CP3 authority at action time.
- Empty/partial conditions are documented separately from lifecycle statuses.
