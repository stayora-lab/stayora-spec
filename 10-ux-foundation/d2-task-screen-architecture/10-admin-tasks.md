# Stayora Admin — Task Architecture

**Surface:** Stayora Admin · **V0:** MUST BUILD scoped governance/manual assistance.

| ID | Task | Type | Structural home | Authority boundary |
|---|---|---|---|---|
| ADM-T1 | Review/assist onboarding eligibility and relationships | Manual-assisted | `ADM-01 Applications & Eligibility` | Explicit staff function/resource scope |
| ADM-T2 | Support Property representation and Verification cases | Manual-assisted | `ADM-02 Property & Verification` | Verification ≠ Identity authority |
| ADM-T3 | Inspect Inventory conflicts and External Accommodation reconciliation | Attention | `ADM-03 Inventory & External Exceptions` | Evidence/audit; no invented policy |
| ADM-T4 | Govern operational Incident exceptions | Attention | `ADM-04 Incident Governance` | Finding/Responsibility/Consequence remain distinct |
| ADM-T5 | Inspect Payment/Money exceptions | Attention | `ADM-05 Money Exceptions` | Payment ≠ Entitlement ≠ Settlement ≠ Payout |
| ADM-T6 | Inspect audit/provenance and relevant destination/lead records | Supporting | `ADM-06 Audit & Provenance` | Need-to-know, function-scoped |

Admin is not a universal super-user and does not bypass policy or unresolved Founder decisions. No CRUD panel for every table is justified.
