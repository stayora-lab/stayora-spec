# Information Hierarchy (Semantic Only)

For each screen concept, structure information by purpose rather than visual treatment:

1. **Primary information:** truth needed to complete the main user job (for example Request context, Stay dates, derived Availability).
2. **Supporting information:** context that explains or enables the job (Property, Destination, relationship, provenance).
3. **Attention/exception information:** pending Request, conflict, Payment `UNKNOWN`, Incident, onboarding pending or Stay exception.
4. **Action-decision information:** consequences, authority-dependent options and policy dependencies needed before a consequential action.
5. **Context/provenance information:** source, evidence, timestamps, responsibility and audit context where need-to-know permits.

This document does not choose tabs, cards, columns, visual emphasis, components, copy or pixel hierarchy.
