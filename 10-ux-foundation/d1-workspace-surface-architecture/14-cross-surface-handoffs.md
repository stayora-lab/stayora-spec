# Cross-surface handoffs

| Handoff | Trigger / truth projected | Receiving responsibility | Required authority | Does not transfer |
|---|---|---|---|---|
| Public → Host | Direct Request created | Host/Booking Authority decision | Request path + Host authority | Public user does not gain Host authority |
| Sale → Host | Sale creates Request | Host/authorized Co-host accepts/rejects | Sale scope; Booking Authority separate | Sale does not accept or reserve |
| Host → Guest Stay Access | Booking confirmed / legitimate external Stay | Guest access and operations | Stay/access relationship | Does not expose internal economics |
| External Commerce → Inventory/Stay | External fact accepted/recorded | Inventory/Stay/Host/Operations | Explicit Inventory authority for commitment | Does not create Stayora Booking |
| Host → Butler | Stay/readiness responsibility assigned | Butler operational context | Assignment and action scope | Does not grant commercial/Inventory authority |
| Butler → Host/authority | Incident/evidence/readiness | Authorized operational/Inventory/Quality decision | Reporting vs decision authority | Evidence does not become Block/consequence |
| Operations → Inventory | Evaluated issue supports canonical basis | Inventory authority | Explicit Inventory action | Butler/BQL visibility does not mutate |
| Stay → completion | Checkout/evidence reaches completion evaluation | Stay/Operations/Money/Quality as scoped | Completion authority/policy | Checkout does not release or complete automatically |
| Admin ↔ contexts | Exception/onboarding/reconciliation need | Relevant domain context | Admin function/reason/audit | Admin does not bypass TBD or impersonate |
