# F2. Spacing, density and layout

**Status:** spacing rhythm and density direction are **ACCEPTED — F2 FOUNDER VISUAL DECISION**; hierarchy rules remain accepted from F1.

## Accepted rhythm

Use the small rhythm `8 / 12 / 16 / 20 / 24 / 32` as the default reference. A value outside this set needs a component or content reason, not personal preference.

- `8`: icon-to-label, compact metadata gap.
- `12`: field/control inner grouping, list row sub-gap.
- `16`: standard control and card padding step.
- `20`: panel section rhythm and comfortable row separation.
- `24`: card/panel padding or section gap.
- `32`: page section or major shell gap.

## Density profiles

| Surface | Profile | Hierarchy and action emphasis |
|---|---|---|
| Public Marketplace | Comfortable / visual | Image/property context, dates, public price, derived Availability/Bookability and Request intent. |
| Guest Stay Access | Comfortable / action-focused | Current Stay, access, arrival/departure and help; keep the next legitimate action obvious. |
| Host Workspace | Medium-to-dense | Requests, Booking/Stay distinction, Unit × Time, Inventory basis, attention and authorized action. |
| Sale Workspace | Medium-to-dense | Scoped supply, relationships, options, attribution and Request handoff; no Booking authority implied. |
| Operations — Butler | Mobile/action-priority | Today/Assignment, readiness, Stay operations, incident evidence and safe field actions. |
| Operations — Destination/BQL | Dense operational overview | Destination-scoped occupancy, access, services, issues and handoffs; no Host/Booking authority. |
| Stayora Admin | Dense exception/governance | Evidence, provenance, conflicts, manual assistance and scoped financial/quality views. |

These are composition profiles, not screen designs or routes. Dense does not mean tiny; comfortable does not mean decorative.
