# Canonical Request → Booking Interaction

`Discovery/intent → Request creation → Request PENDING → Host decision → revalidation → ACCEPTED or REJECTED → applicable Inventory/payment/confirmation conditions → Booking CONFIRMED only when canonical conditions pass → contextual Host/Sale/Guest/Operations projections`.

Guest intent, Offer/option, Request and Booking remain distinct. Request does not reserve Inventory. Acceptance may enable a finite commitment where canonical, but acceptance is not automatically Booking. A Booking does not become a Stay; Guest Stay Access is a later scoped handoff.
