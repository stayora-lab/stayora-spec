# Interaction Sequence Findings

## A. Sale creates Request

Sale finds scoped supply → checks dates/derived projections → prepares permitted option → captures Guest intent → validates creator/Lead Guest/Staying Party/Payer distinctions → revalidates → creates canonical Request → Sale/Host/Guest projections.

## B. Direct Guest creates Request

Public discovery → Property/Unit/date intent → public truth/bookability → Guest Request entry → optional account path only if canonical → validate → revalidate → canonical Request → Guest/Host projections.

## C. Host inspects Request

Host attention → Request Detail → current accommodation, Guest/creator, Inventory, terms, authority and provenance → action availability categories.

## D. Host rejects

Acting capacity → authority → Request state/scope/Inventory revalidation → reject commitment → canonical rejection or conflict → projections/attention update.

## E. Host accepts

Same checks → accept Request only → applicable Inventory/payment/confirmation conditions → not automatically Booking.

## F–L boundaries

Accepted Request stops at conditions; Payment Attempt follows canonical condition; UNKNOWN routes reconciliation; Booking confirmation updates projections/handoffs; Inventory conflict preserves truth; stale/concurrent action cannot overwrite; manual exception records responsibility and result.
