# Consequential Action Model

Before a consequential action, the projection must expose: current object truth; acting capacity; resource scope; authority dependency; relevant preconditions; and canonical consequence that is actually known. Revalidation occurs at commitment. A consequence preview is used only when the domain supports the consequence. Explicit confirmation is justified by financial, inventory, external, Guest, delegation or hard-to-reverse impact; the exact interaction control is later work.

Applies to Request accept/reject, Owner Block, Inventory intervention, External Accommodation recording, authorized Check-in/Checkout, publication, Butler assignment and relationship correction/revocation. Outcomes must distinguish accepted, rejected, conflict, pending/processing, failed, unknown and manual follow-up.
