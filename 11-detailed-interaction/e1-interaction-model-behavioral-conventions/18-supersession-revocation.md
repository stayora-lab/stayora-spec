# Supersession and Revocation

Use the narrowest canonical semantic: EDIT for permitted mutable detail; CORRECT for factual error; SUPERSEDE for a new effective representation; REVOKE for withdrawal of a relationship/authority/eligibility; RELEASE for an authorized Inventory commitment/block release; EXPIRE for time-bound validity; CANCEL only where the domain explicitly supports it. Do not turn all actions into generic Edit/Delete. Where upstream semantics are missing, keep the branch as a policy boundary.
