# Working Context and Resource Scope

> Status: **STABLE — CHECKPOINT 6 DOCUMENTED; NOT IMPLEMENTATION FREEZE**

Canonical conceptual model:

```text
IDENTITY → WORKING CONTEXT → RESOURCE SCOPE → OBJECT → ACTION
```

Working Context is not Role and does not create authority. One Identity may simultaneously be Primary Host of Property A, Co-host of Property B, Sale in other commercial relationships and Guest of another Stay. Selecting a context changes perspective and navigation only.

Effective permission remains:

```text
Identity + Platform Eligibility + Actor Relationship
+ Authority Capability + Resource Scope + Authority Lifecycle
+ Resource/Destination Policy + Transaction Context
→ Effective Permission
```

Contextual IA must never replace this model. Resource projections must respect relationship scope, destination scope, lifecycle and need-to-know access. Context-specific data visibility is not a new authority grant.

Core IA invariants: one identity, multiple working contexts; context changes perspective, authority determines permission; navigation follows responsibility, not database structure.
